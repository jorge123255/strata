# Shared Mac conversations on iPhone

The iPhone now opens the Mac's conversations, continues the same chat and agent session, and shows current browser and tool activity. New shared chats start in Manual mode. Existing chats retain their working folder, model and permission mode. Closing the phone leaves Mac agent work running. Stop and Allow/Deny use the existing per-chat control paths.

## Data and access

After pairing has first been enabled, the Mac imports its existing web-view history into `data/conversations.json`. A fresh installation creates no shared catalog before that opt-in; enabling pairing imports history immediately without a restart. If a desktop response began before that first opt-in, its conversation is imported after that response finishes so a partial snapshot cannot replace the completed answer. Disabling pairing retains the local catalog. Session IDs and message IDs remain stable. Turn-bound callbacks prevent delayed output or Stop completion from changing a newer response. Revision checks reject stale renderer snapshots; deletion tombstones prevent an old cache from restoring removed chats. Projected messages and action cards persist independently of a connected screen. The Mac's own stream and the shared observer apply each frame once.

The TLS bridge requires the existing paired-device token for every conversation operation, including reads, and checks revocation again after awaited responses. Continuing a chat accepts only a message; the phone cannot supply another folder, model, permissions or history. Provider configuration, raw tool arguments and runtime protocol are omitted from phone responses. User conversation text and readable tool results are shared with paired devices. The Mac event stream filters private conversation snapshots for each subscriber using the same exact loopback socket, Host and Origin checks as the conversation API; public operational events retain their prior behavior. Earlier private iPhone-only chats stay separate.

Browser cards show actions, addresses, states, approval requests and available text results. They do not stream browser pixels. The iPhone refreshes the selected conversation while Chat is visible and the app is active.

## Recovery of a previously incomplete desktop cache

The original Mac cache held only a strict prefix of the most recent assistant reply. Its persisted Harness session log contained the later text and completed tool results. With Strata closed, a private, hash-checked candidate restored that one reply from 3,051 to 3,936 characters and 51 to 68 tool cards. All 18 existing message IDs, earlier messages and both other conversations were retained. A byte-for-byte original catalog backup and the immutable durable log were preserved. The recovered text and 68 terminal tool cards were confirmed through the installed app and visibly in the Mac conversation after reopening.

An unmatched durable turn was left uninserted because its origin as a visible user submission was not independently established. Existing file cards were retained; transient file-diff counts were not reconstructed. Private recovery details and hashes stay outside Git.
