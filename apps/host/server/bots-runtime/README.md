# Bots provider runtime

`createBotRuntime({ stateDir, env?, fetch?, commands?, remoteSSH? })` returns:

- `providers()`: installed CLI versions, public readiness and account help. CLI presence does not prove a signed-in account or model entitlement. No credentials are returned.
- `run({ bot, sessionId, message, history, signal, onFrame, requestPermission, executeTool, checkpoint, onCheckpoint, tools, modelRequest? })`: one provider turn. Returns `{ text, checkpoint, tokensIn, tokensOut }` and throws on provider failure or Stop.
- `close()`: stops this runtime's owned runs. It does not attach to or stop a user's existing CLI processes.

Frames use the existing conversation reducer: `delta`/`reasoning` have `text`; `agent-tool` has a `tool` card; `stats`/`done` have token counts; `error` has `message`. Providers only supply thinking events they actually emit. A status indicator is not synthesized reasoning.

`tools` are MCP definitions (`name`, `description`, `inputSchema`). `executeTool(name, args, id)` must enforce the bot's current policy and capability and return an MCP result, including image blocks where relevant. The host owns the workspace boundary, tool ledger, tool cards and approvals. The private MCP stdio bridge only exposes this allowlist. Its socket and definitions live in a private temporary directory and are removed after the run.

Claude uses the official pinned Agent SDK and installed `claude` executable, with built-ins and inherited MCP settings disabled. Grok and Kimi use ACP with a generated tool profile that permits only Strata MCP tools; no native shell, edit, subagent or automatic approval flags are enabled. These profiles are private files under `stateDir/profiles` and remain available for native session restoration. ACP session restoration replays old messages, so projection starts only after loading finishes. Codex uses app-server, a native read-only sandbox and host-owned dynamic tools. Native command/file approval is always denied: coding mutations must use the host tools. Resolved inherited MCP servers are each explicitly disabled (an empty table would only deep-merge), and the thread MCP inventory must contain no tools before sending a model prompt. Native shell, hooks, plugins, apps and multi-agent features are disabled. Broader permission grants and unsupported server requests fail closed.

Grok model discovery runs the installed CLI's `models` command without opening a native session or sending a prompt. Its account's returned model IDs and default form the catalog. Only public name and effort fields from matching entries in the CLI's model cache are projected; cache credentials and account identity are never returned. There is no guessed model or effort fallback. A missing, malformed or symlinked cache keeps the verified IDs with Provider default effort. An explicit effort is still verified against the selected ACP session and confirmed before a prompt. This was checked against Grok CLI 1.0.62. Native Grok uses the existing CLI account; the separate `xAI · Grok` connection in Models uses an owner-supplied xAI API key and retains its own models.

Devin CLI uses its native ACP endpoint and the account already signed in on the execution computer. The adapter was checked against CLI 3000.11.92. Each Strata conversation has a private provider working folder, HOME, XDG config/cache and session directory. Native XDG data storage remains on the owning account, so credentials are neither copied nor returned. The adapter disables external config sources, plugins, hooks, automatic updates, native file/shell/web/skill tools and native subagents. It verifies the effective config, empty rules/hooks, completed empty plugin inventory, builtin-only skill inventory, and the exact current Strata MCP server, socket, tool schemas and empty resource list before each prompt. Unsupported or changed protocol responses stop before the message is sent. Native Code mode (`accept-edits`) is explicitly selected and confirmed so Strata MCP tools can perform approved changes. Devin's native Ask mode would block every MCP tool without a read-only annotation. The host broker owns Strata's Ask, Plan and Bypass policies; tools keep their actual effects and are never mislabeled read-only. Native permission requests always remain denied; an exact current-turn MCP tool identity can acknowledge transport once.

Devin model discovery runs `models list --format json` without a model prompt. The catalog uses the returned variant IDs and names; it does not infer effort levels from a model name. Adaptive and Fusion variants are excluded because this adapter owns one provider brain and team coordination. An explicitly supplied effort must appear in the selected ACP session and be confirmed by `session/set_config_option` before a prompt. Native session restoration uses the same private chat state and a fresh bridge socket; replayed messages do not reenter the shared transcript. Stop sends `session/cancel` and stops only the owned process group. A native session error preserves Strata history and remains visible; there is no automatic prompt replay.

Ollama Cloud uses its OpenAI-compatible streaming endpoint or an explicitly selected cloud alias in the signed-in local daemon. It never sends a cloud key to the loopback daemon. It performs no automatic alias download and never silently falls back to local Strata or Maya inference. HTTP retries never replay a completed tool mutation. The host transcript supplies stateless history; native providers persist resume identifiers through `onCheckpoint`.

Local execution uses the selected computer's native provider account. SSH execution delegates to `createRemoteBotSSH` before checking the local workspace: its workspace, code, browser and desktop tools belong to the selected SSH account. Linux supports coding and a headless browser; native desktop control requires macOS. An inference API connection alone is not an execution transport. Native resume errors remain visible; the runtime does not silently start another session and lose native context.

`createRemoteBotSSH()` exposes `probe(execution)`, `prepare(execution, { signal?, installBrowser? })`, `run(input)`, `cua(execution, operation, payload, { signal? })` and `close()`. SSH profiles contain a host or configured alias and optional user and port. An omitted port keeps the system SSH configuration. The transport requires existing key authentication and a verified host key, disables agent forwarding and uses a fixed remote command; app values travel as bounded JSON over stdin.

Probe is read-only. Explicit Prepare installs a versioned private helper under `~/.local/share/strata/bot-workers`, with a locked SDK/browser dependency set and verified asset hashes. If needed, it downloads the official Node.js 24.12.0 archive into a private runtime directory and verifies its pinned SHA-256 before extraction. It does not install system packages, provider CLIs or accounts, or change a running model service. Chromium download is a separate explicit preparation option. Model account credentials remain on their execution host.

The `configured` provider accepts only the host-bound `modelRequest` callback. On SSH, the worker requests inference through the Mac over the existing private channel; connection keys and inference URLs stay on the Mac. Tool execution stays on the SSH computer. Native checkpoints are bound to both the SSH profile and a private identity of its account/computer, so a changed target cannot resume another machine's conversation.

Each SSH turn has a heartbeat lease, remote approval RPC and an owned process registry. Stop, EOF or lease expiry revoke future tools and pending approvals, stop owned provider/tool children, and wait for cleanup before acknowledging completion. A lost acknowledgement returns `ssh_cleanup_unconfirmed`; it never returns a successful Stop or automatically replays a turn. Read-only probe reports active worker processes, allowing the host to keep an uncertain target blocked until it verifies cleanup. Computer turns also hold a private cross-process lease on the remote account.

`computerMode: 'cua'` selects this bot's persistent isolated CUA computer. All code, browser and computer tools run inside that Space. Native provider working directories are separate private host folders; a logical `/workspace` path is never treated as a host folder. CUA preparation is explicit and separate from ordinary SSH preparation. Viewer `state` and `probe` never start a computer or inference provider. `start`, `control` and `stop` use the selected host's CUA backend and the same per-bot lease as agent turns. Ordinary agent Stop preserves the Space. An unconfirmed guest command returns `cua_cleanup_unconfirmed`, preserving a per-Space block even if SSH cleanup was acknowledged. Only a confirmed explicit computer stop clears that private marker.

Explicit computer Stop reboots only the owned guest, proves a changed kernel boot identity, and then pauses it before clearing pending command records. It preserves the disk. The released CUA SDK cannot resume a QEMU computer that has stopped unexpectedly; Strata retains that disk and asks the user to create another bot. It never silently deletes or recreates the computer. CUA preparation on supported Ubuntu accounts downloads signed official packages into an isolated private APT cache and extracts QEMU without installing system packages or changing KVM groups. Accounts the released SDK cannot run because of KVM permissions remain unavailable with an actionable message. The private privilege-denial wrapper prevents escalation; it does not imply software-emulation support.

The released Python SDK refuses to connect to a paused QEMU instance. Explicit Start and computer Stop use only the official CLI bundled in that pinned private wheel to resume the exact owned sandbox, retaining its private VMM and sandbox state directories. The subprocess has a credential-free environment, an owned process group and a bounded lifetime; metadata must confirm Running before the SDK connects. Read-only state uses metadata directly and never resumes a paused computer.

For a Mac app production package, install host dependencies with `npm ci --omit=dev --omit=optional`. The SDK's optional platform CLI binary is unnecessary because Strata uses the user's installed CLI. Keep `node_modules` beside the packaged host server; it includes the SDK and production browser driver library. Browser binaries are managed separately by the host computer tool implementation.

Validation: `node --test tests/bots-devin.test.mjs tests/bots-runtime.test.mjs tests/bots-ssh.test.mjs tests/bots-cua.test.mjs` exercises isolated protocol fixtures, stream parsing, approval denial, session ownership, image results, credential redaction and Stop. An actual harmless descendant that ignores TERM verifies process-group escalation after its leader exits. SSH fixtures use real stdio child processes and a scratch account directory to test read-only probe, private npm preparation, approval and inference RPC, EOF/heartbeat cancellation, checkpoint identity, cross-worker leases, and separate CUA cleanup failure. They do not download Node or CUA images, send live model prompts, contact production SSH hosts, or prove provider entitlement. Live acceptance is recorded separately by the host integration work.
